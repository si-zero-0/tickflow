# 决策记录（ADR）

> 只记"为什么"，不记"怎么做"。每条给出结论、代价、翻案条件。

## D1 · 保留零构建，不引 Vite/Webpack
**2026-11-17 · 现状**

- 结论：仍是原生 `<script>` + 全局 `TF`，只加一层注册表。构建工具只负责打包，不参与开发。
- 理由：改动后的首屏仍是 9–15ms；引构建器会把 `file://` 双击调试弄坏，也会让改一行要等 HMR。
- 代价：没有 tree-shaking、没有 TS 类型、模块顺序靠 `verify.mjs` 守。
- 翻案条件：单文件超过 200KB，或模块数 > 20，或需要 npm 包依赖（届时改 ES Module + import maps，不引打包器）。

## D2 · 插件默认在渲染层，主进程侧后置
**2026-11-17**

- 结论：插件先只做渲染层（`commands`），`entry.main` 先留字段不执行。
- 理由：主进程插件 = 任意代码执行，权限模型没定之前开放等于开后门。
- 代价：需要 fs / 网络的插件暂时做不了。
- 翻案条件：`permissions` 白名单 + 宿主 patch 全局 API 的机制跑通之后（backlog P2）。

## D3 · 不用 portable，只出 NSIS
**2026-11-16 实测**

- 结论：发布形态 = 安装版（NSIS）+ 绿色版（拷目录），永久放弃单文件便携版。
- 理由：portable 是 NSIS 自解压，每次启动解压 266MB，实测 33 秒；安装版 1.5 秒。
- 代价：分发时对方要过一次安装向导（可静默 `/S`）。
- 翻案条件：Electron 官方支持真正的单文件挂载（不是自解压）。

## D4 · `src/main` 与 `src/renderer` 平级，不合并
**2026-11-17**

- 结论：主进程、渲染层各自独立目录，`package.json` 留在 `src/main`（electron-builder 要求应用清单在应用根）。
- 理由：渲染层可以单独拷出来双击跑；主进程的 `node_modules`（electron 全家桶）不污染前端目录。
- 代价：仓库里有两个 `package.json`，命令要带 `--prefix src/main`。
- 翻案条件：迁到 pnpm workspace 且工具链支持多包构建。

## D5 · 产物只留最新一份，路径写死
**2026-11-17**

- 结论：`build/dist`、`build/release` 固定路径，`build.mjs` 每次先 `rm -rf`。
- 理由：旧工作区用 `dist2…dist23` / `release2…release18`，堆了 11.85 GB，且分不清哪个能发。
- 代价：不能并行打两个版本（确实不需要）。
- 翻案条件：需要同时维护多版本分支时，改为 `build/<version>/`。
