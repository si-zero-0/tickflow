# 交付前检查清单 · TickFlow

每次交付前逐项执行，不得跳过。汇报时按本清单编号给出结果；未做或未通过必须写明原因。

## 1. 阶段门（实跑，数字以当次为准）

- [ ] `npm run verify` 全绿，记录通过项数
- [ ] `npm test` 全绿，记录用例数
- [ ] `npm run stage` 成功，记录同步文件数
- [ ] 涉及主进程 / 窗口 / 截图能力时，额外跑 `cd src/main && npx electron stage --smoke`

## 2. 运行验证（最新构建）

- [ ] 用本轮 `stage` 产物重启演示实例，确认旧实例已退出
- [ ] 本轮改动的页面逐页打开，确认可交互
- [ ] 冒烟结果 `consoleErrors` 为空
- [ ] 记录当前运行版本与进程 PID

## 3. 截图（当前构建实拍）

- [ ] 全部截图来自本轮构建，不用历史图或参考图
- [ ] 画面有真实示例数据，无空态、无报错、无遮挡残留
- [ ] 无本机绝对路径（`C:\Users\...`、`%TEMP%`）、无账号/隐私信息
- [ ] 图片存放路径正确、大小写一致，单张 ≤ 300KB
- [ ] 逐张打开检查内容，确认没有裁切、压字、错位

## 4. 公开内容审查

- [ ] README 与对外文档无内部口径、无本机路径、无第三方品牌名、无占位地址
- [ ] 文档内所有图片链接、相对链接均存在
- [ ] Releases、仓库、Issues、反馈链接可达（HTTP 200 或明确重定向）
- [ ] 图片与文档路径大小写正确

## 5. 版本与一致性

- [ ] 版本号三处一致：`package.json`、`src/main/package.json`、`TF.VERSION`
- [ ] `src` 与 `src/main/stage` 文件清单、版本号一致
- [ ] 发布时 tag 与 Release 资产齐全，资产哈希与本地产物一致

## 6. 回归

- [ ] 本轮受影响的功能点抽验通过
- [ ] 未受影响的核心路径（新建任务、切换视图、设置、导入导出）不回归
- [ ] 1080 / 1400 宽度下无横向溢出或遮挡
