# 项目过程与阶段门 · TickFlow v1.13.0

> 给实现者/评审者的流程约束。不是建议，是阶段门。

---

## 1. 角色

| 角色 | 职责 |
|---|---|
| 实现者（Trae） | 按任务表改代码、跑测试、写 `IMPLEMENTATION-NOTES.md` |
| 评审者（人） | 看 PRD/UI 规范、验收截图、抽查关键交互 |
| QA（人/代理） | 按 `07-TEST-PLAN.md` 跑矩阵、出缺陷表、给路由判定 |

## 2. 阶段门

```
G0 基线
  verify 8/8 · test 45/45 · stage 26 · 启动截图
   ↓
G1 Token/外观
  9×2 对比度 · 切换不闪白 · 迁移不丢数据
   ↓
G2 主壳/设置/组件
  1060/1400/4K · 设置 8 类 · 12 视图无白屏 · 0 console error
   ↓
G3 M3 双岛
  三态 · 同步 P95<100ms · 5 条提醒不丢不重 · 关闭回退
   ↓
G4 回归
  v1.12 功能全绿 · 导入导出/快照 · 键盘/IME/reduced motion
   ↓
G5 发布
  1.13.0 · verify/test/stage · 安装包可启动 · 文档更新
```

每个门不通过，不进入下一阶段；不要“先做完再补测试”。

## 3. 变更控制

- 任何超出 `01-PRD` P0/P1 的功能，先记录到 `IMPLEMENTATION-NOTES.md` 的“偏差/假设”，不要直接做。
- 任何新增依赖、主进程新能力、数据结构变更，必须在 notes 里写原因/影响/回滚。
- 不删除旧字段；只新增/迁移。
- 不改 `docs/iteration-112/` 历史文档；新决策写 `docs/handoff/`。

## 4. 每阶段产出

| 阶段 | 产出 |
|---|---|
| G0 | 基线数据、代码地图 |
| G1 | token/方案实现、对比度表、迁移单测 |
| G2 | 主壳/设置/外观截图、12 视图回归、0 console error |
| G3 | 双岛三态截图、同步延迟、提醒队列测试 |
| G4 | 全量回归报告、缺陷表（S1/S2/S3） |
| G5 | 版本 1.13.0、安装包、README/CHANGELOG、交付总结 |

## 5. 缺陷路由

- 源码 bug → 实现者修，附文件:行/复现/期望/实际。
- 测试脚本 bug → QA 自修。
- 文档歧义 → 以 PRD Assumptions 为准，记录偏差；不阻塞。
- S1/S2 未清零 → 不放行。
